Примеры тестов покрывающие часть сценариев.

| Название                                                                 | Тип            | Компоненты                                                                                                                  | Предусловия                                                                                        |
|--------------------------------------------------------------------------|----------------|-----------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------|
| 01 Happy path: AUTH→ALLOW→CAPTURE→PAYOUT→LEDGER+NOTIFY                   | e2e            | Orchestrator, Payment, FraudCheck (mock), PSP (mock), Payout (mock), Ledger, Notification, Kafka/Rabbit, PostgreSQL, Redis  | `authOk=true`, `fraudDecision=ALLOW`, `captureOk=true`, `payoutOk=true`; чистая БД; загружен BPMN  |
| 02 AUTH fail → release + cancelled                                       | e2e            | Orchestrator, PSP (mock), Notification                                                                                      | `authOk=false`                                                                                     |
| 03 Fraud DENY → release + cancelled (+ security)                         | e2e            | Orchestrator, FraudCheck (mock), PSP (mock), Security notifier, Notification                                                | `fraudDecision=DENY` после успешной авторизации                                                    |
| 04 REVIEW → manual ALLOW → capture→payout                                | e2e            | Orchestrator, FraudCheck (mock), PSP (mock), Payout (mock)                                                                  | `fraudDecision=REVIEW`; в течение 20 мин приходит `REVIEW_ALLOW`                                   |
| 05 REVIEW без ответа → cut‑off auto APPROVED                             | e2e            | Orchestrator (таймеры), FraudCheck (mock), PSP (mock)                                                                       | `fraudDecision=REVIEW`; таймер cut‑off сокращён до 30 секунд (например) для теста                  |
| 06 CAPTURE fail окончательно → refund/release → cancelled/refunded       | e2e            | Orchestrator, PSP (mock), Notification                                                                                      | Все попытки capture → ошибка/timeout; проверка возврата/разблокировки и терминального статуса      |
| 07 PAYOUT fail окончательно → refund + ledger reversal + notify fail     | e2e            | Orchestrator, Payout (mock), PSP (refund), Ledger, Notification                                                             | Capture ok; все попытки payout → ошибка; ожидаем refund и reversal                                 |
| 08 Post‑facto FRAUD DENY после payout → immediate refund                 | e2e            | Orchestrator (boundary message), PSP (refund), Ledger, Notification                                                         | Дошли до payout; затем приходит `POST_FACTO_FRAUD_DENY`                                            |
| 09 Идемпотентность: дубликат запуска (PAYMENT_CREATED)                   | интеграционный | Orchestrator, Payment, PostgreSQL, Kafka/Rabbit                                                                             | Дважды отправить старт с одинаковым `sagaId/idempotencyKey`; только один процесс и один эффект     |
| 10 Восстановление: рестарт оркестратора во время ожидания REVIEW/cut‑off | интеграционный | Orchestrator, PostgreSQL                                                                                                    | Процесс ждёт сообщение/таймер; перезапуск; ожидание и таймер продолжают работать корректно         |
